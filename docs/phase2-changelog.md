# Phase 2 交付记录

复核日期：2026-10-25。版本：0.3.0。

完成逐角色模型与受限后备链、四级有效配置及不可变快照、根 Run/角色预算预占和结算、有限 Schema 修复、Skills 隔离导入与人工绑定、MCP 工具级授权及持久调用凭据，并接入原有交付工作流和 CLI。

本次复核直接修复了两处问题：

1. MCP 发现阶段原先只按工具名称过滤，可能在角色缺少对应 Capability 时启动已登记的本地服务。现在先检查受信工具策略与有效 Capability，生产部署、秘密管理和记忆审批能力继续交给独立执行器；无权使用的服务不会为了获取元数据而启动。
2. 写入审批原先只有参数摘要，审批人无法核对具体目标。现在审批单提供脱敏后的参数结构和内容，`phase2-status` 展示本项目审批单并校验项目访问权；原参数哈希、服务版本、配置摘要、时效及一次性消费约束保持绑定，凭据内容及敏感字段值不进入预览或审计。

此前同时补齐了 UX/研发出口拒绝后的有界返工、跨模型共享 Schema 修复次数、MCP 启动文件摘要校验，以及拒绝事件在事务回滚后的独立记录。

最终全量验证为 **383 passed，0 failed，0 skipped**，其中包括 80 项 Phase 2 专项和 2 项真实 Java 集成；MCP 专项实际运行本机 stdio、HTTP、SSE。0.3.0 Wheel 完成独立安装、配置命令验证及 42 个模块的源码一致性校验，依赖和差异格式检查通过。

今天复测 DeepSeek 模型列表预检仍返回 **HTTP 401**，没有成功的在线生成证据。Phase 2 的实现与本地验收已完成；真实模型端到端效果需要可用凭据后继续验证。生产发布、OS 沙箱及长期记忆发布属于后续阶段。
